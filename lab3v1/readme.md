[Файл відкрито]: app_explicit.log

=== Сценарій 3: Автоматична фіналізація (GC) ===
[Файл відкрито]: app_gc.log
[Запис у app_gc.log]: Запис об'єктом без Dispose
Запуск збирача сміття...
[Деструктор]: Автоматичне вилучення через GC для app_gc.log
[Dispose]: Закриття файлу app_gc.log

Програму завершено.
[Dispose(true)]: Очищення керованих ресурсів для app_using.log
[Dispose]: Закриття файлу app_using.log


Під час виконання лабораторної роботи досліджено керування некерованими ресурсами та реалізовано патерн Dispose в C#:
Оператор using є найбезпечнішим способом, оскільки гарантує миттєвий виклик Dispose() навіть у випадку виникнення помилок.
Явний виклик Dispose() дає повний контроль над закриттям ресурсів, а GC.SuppressFinalize(this) прискорює робочий цикл, виключаючи об'єкт з черги фіналізації.
Деструктор (~FileLogger()) слугує "страховкою": якщо розробник забув закрити ресурс, Garbage Collector під час збирання сміття автоматично викликає Dispose(false) для звільнення некерованих ресурсів.
